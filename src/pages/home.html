> Fig.01 — the parsing problem

Messy input → LLM-ready context.

  1. 01

    Messy input

    A phone photo, not a clean PDF.

    Skewed page, a coffee ring, a margin scribble, a printed diagram and a running header — the kind of input real students actually send.

  2. 02

    Crop & segment

    Find the regions that carry meaning.

    Layout detection separates body text, the figure and the handwritten note, then crops each region upright so nothing is lost to the noise around it.

  3. 03

    Parse & clean

    Turn pixels into structure.

    OCR reads the text, broken lines are rejoined, page furniture is dropped, the equation stays an equation and the figure gets a caption it can be searched by.

  4. 04

    Chunk with provenance

    Small pieces that remember where they came from.

    Text and figure become self-contained chunks, each tagged with section, page and links to its neighbours — so “see Fig. 3.2” still points somewhere.

  5. 05

    Embed

    Meaning becomes a position.

    Every chunk — text and image description alike — is embedded into a vector space where related ideas land near each other and can be found by meaning.

  6. 06

    Retrieve & answer

    The agent answers from the page.

    A student's question pulls the nearest chunks, the agent packs them into context and answers — citing p.42 and Fig. 3.2 instead of guessing.

> Deep dive — the full workflowBack to Case 01 ↑

From messy input
to grounded answers.

Most of the quality in an agent's answer is decided before the model ever runs. This is how I approach turning unstructured, multimodal material into context an LLM can use — seven stages, each with an output you can inspect.

01 Ingest02 Parse & clean text03 Crop & read images04 Structure05 Embed06 Connect the agent07 Retrieve & respond

Traced example One phone photo of a physics textbook page — p.42, body text, a printed trajectory diagram, a margin note and a coffee ring — followed through all seven stages to one student question.

  1. 01

    Ingest

    Take input as it really arrives.

    PDFs, scans, screenshots and phone photos arrive in different formats and quality. Each item is typed, split into pages and given a source record, so every later chunk can point back to where it came from.

    in
    files · text · images
    out
    typed items + source ids
    uses
    format detection · page & frame splitting · source metadata
  2. 02

    Parse & clean text

    Strip the noise, keep the meaning.

    Text is read (OCR where there is no text layer), then normalised: hyphenated lines rejoined, running headers and page numbers dropped, equations and lists kept as structure rather than flattened prose.

    in
    raw text · OCR output
    out
    clean, sectioned text
    uses
    OCR for photos & scans · de-duplication · layout-aware cleanup
  3. 03

    Crop & read images

    Find the part of the image that matters.

    The page is segmented into regions — body text, figure, handwriting. The diagram is cropped tight to its bounds, then described and labelled so an agent knows what it shows and which paragraph cites it.

    in
    page photo
    out
    cropped regions + descriptions
    uses
    region detection · smart cropping · captions & labels
  4. 04

    Structure

    Organise everything into one shape.

    Clean text and image regions merge into chunks with a title, a place in the hierarchy, a link from the figure to the paragraph that cites it, and metadata the agent can filter on.

    in
    text + regions
    out
    structured multimodal chunks
    uses
    semantic chunking · cross-references · schema & metadata
  5. 05

    Embed

    Turn chunks into vectors.

    Each chunk, and each figure description, is encoded as an embedding — a vector of its meaning — and stored with its metadata in an index built for semantic search.

    in
    structured chunks
    out
    vector index
    uses
    text & image embeddings · metadata filters · re-index on change
  6. 06

    Connect the agent

    Give the agent context as a tool.

    Retrieval is wired in as a tool. The agent decides when to search, rewrites the question into a better query and chooses filters, combining what it finds with its own plan and memory.

    in
    user goal + index
    out
    retrieval calls
    uses
    retrieval as a tool · query rewriting · agent memory
  7. 07

    Retrieve & respond

    Answer with the right context.

    Matching chunks are retrieved and re-ranked, packed into the prompt with their sources, and the model answers from them — pointing at the page, figure or line it used.

    in
    question
    out
    grounded, cited answer
    uses
    semantic search · re-ranking · citations

Why structure first

Clean, labelled chunks keep retrieval precise and stop noise, boilerplate and broken layouts from leaking into prompts.

Why images matter

Diagrams, tables and handwriting carry meaning text extraction drops. Cropping and describing regions makes that meaning searchable.

Why retrieval

The agent gets only the context a question needs, with sources it can cite — better answers, fewer guesses.
